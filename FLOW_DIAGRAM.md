# ゴミカレ 処理フロー解説

このドキュメントでは、ゴミカレの2つの主要な機能の処理の流れを図解で説明します。

---

## 📄 フロー1：PDFアップロード → Googleカレンダー登録

ユーザーがゴミ収集カレンダーのPDFをアップロードしてから、Googleカレンダーに予定が登録されるまでの流れです。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  ① ログイン                                                              │
│  ユーザー ──[Googleでログイン]──► Next.js ──► Supabase Auth             │
│                                              ※ Googleのリフレッシュ     │
│                                                トークンをDBに保存        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  ② PDFアップロード                                                       │
│                                                                         │
│  ユーザー ──[PDFを選択]──► Next.js                                      │
│                              │                                          │
│                              ├──► Supabase DB                          │
│                              │    「処理中リスト（Job）」に登録          │
│                              │    ステータス: pending                   │
│                              │                                          │
│                              ├──► 署名付きURL（Presigned URL）を取得    │
│                              │                                          │
│                              └──► Cloudflare R2                        │
│                                   PDFを直接アップロード                  │
│                                   ※ Vercelのファイルサイズ制限を回避    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  ③ 解析ジョブ開始                                                        │
│                                                                         │
│  Next.js                                                                │
│    │                                                                    │
│    ├──► Supabase DB: ステータス更新 (pending → processing)              │
│    │                                                                    │
│    ├──► AWS Lambda を非同期呼び出し（火をつけて即座に応答）               │
│    │                                                                    │
│    └──► ユーザーへ「処理開始しました」を返答                             │
│                                                                         │
│  ユーザー ──[Supabase Realtime で状態を購読]──► 完了まで待機             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  ④ Lambda による解析・登録処理（バックグラウンド）                       │
│                                                                         │
│  AWS Lambda                                                             │
│    │                                                                    │
│    ├── [1] Cloudflare R2 からPDFをダウンロード                          │
│    │                                                                    │
│    ├── [2] Google Gemini API へ送信                                     │
│    │        PDFをアップロードし「予定データを抽出して」と指示            │
│    │        ↓ レスポンス                                                │
│    │        JSON形式で予定リストが返ってくる                            │
│    │        例: {"date": "2026-04-03", "category": "燃えるごみ"}       │
│    │                                                                    │
│    ├── [3] Supabase DB からユーザーのGoogleリフレッシュトークンを取得   │
│    │                                                                    │
│    └── [4] Google Calendar API へ予定を一括登録                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
                │
         ┌──────┴──────┐
         │ 成功         │ 失敗
         ▼             ▼
┌──────────────┐  ┌──────────────────────────────────┐
│              │  │                                  │
│ Supabase DB  │  │ Supabase DB                      │
│ ステータス更新│  │ ステータス更新 (failed)           │
│ (completed)  │  │                                  │
│              │  │ ※ 重大な障害時（クラッシュ等）は  │
│              │  │   AWS SQS (DLQ) にエラーを退避   │
└──────┬───────┘  └──────────────┬───────────────────┘
       │                         │
       ▼                         ▼
┌──────────────────────────────────────────────────────┐
│  ⑤ ユーザーへ通知（Supabase Realtime）                │
│                                                      │
│  ✅ 成功: 「カレンダーへの登録が完了しました！」      │
│  ❌ 失敗: 「処理中にエラーが発生しました」            │
└──────────────────────────────────────────────────────┘
```

### 処理フローのポイント

| ステップ | 担当コンポーネント | 役割 |
|---|---|---|
| ログイン・認証 | Supabase Auth | Google OAuthによるログインとトークン管理 |
| PDFの保存 | Cloudflare R2 | サイズ制限を回避しPDFを直接保管 |
| ジョブ管理 | Supabase DB | 処理の進捗状態を `pending → processing → completed/failed` で管理 |
| AI解析 | AWS Lambda + Gemini | PDFからゴミ収集日データをJSON形式で抽出 |
| カレンダー登録 | Google Calendar API | 抽出した予定データをカレンダーに一括登録 |
| リアルタイム通知 | Supabase Realtime | 完了・失敗をブラウザへ即時プッシュ |

## 💬 フロー2：LINEメッセージ・写真送信 → 返信

ユーザーがLINEでメッセージや写真を送信してから、ボットが返信するまでの流れです。

### 前提：アカウント連携フロー

LINEボットを使うには、事前にゴミカレアカウントとLINEアカウントを連携する必要があります。

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│  アカウント連携（初回のみ）                                     │
│                                                                │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │  [ゴミカレ ダッシュボード]                                 │ │
│  │                                                          │ │
│  │  ① 「コードを生成」ボタンを押す                           │ │
│  │  ② 6桁のワンタイムコードが発行される（有効期限：10分）    │ │
│  │     例: 483921                                           │ │
│  └──────────────────────────────────────────────────────────┘ │
│                         │                                      │
│                         ▼                                      │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │  [LINE Bot トーク画面]                                     │ │
│  │                                                          │ │
│  │  ③ 発行されたコードをLINEに送信                           │ │
│  │     送信内容: 「483921」                                  │ │
│  └──────────────────────────────────────────────────────────┘ │
│                         │                                      │
│                         ▼                                      │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │  [Webhookサーバー]                                         │ │
│  │                                                          │ │
│  │  ④ コードを検証 → LINEアカウントIDとユーザーを紐付け     │ │
│  │  ⑤ 「連携が完了しました！」と返信                        │ │
│  └──────────────────────────────────────────────────────────┘ │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

```

│                                                                         │
│  ① ユーザーがLINEでメッセージ or 写真を送信                             │

│  ユーザー ──[テキスト例: 「これ何ゴミ？」+ 写真]──► LINEアプリ          │

                │
```

### 処理フローのポイント

| ステップ | 担当コンポーネント | 役割 |
|---|---|---|
| メッセージ受信 | LINE Messaging API | ユーザーのトークをWebhookへ転送 |
| 署名検証 | Webhook (`/api/webhooks/line`) | 不正なリクエストの排除 |
| ユーザー照合 | Supabase DB | LINE IDとゴミカレアカウントの紐付け確認 |
| 画像取得 | LINE Content API | 送信された画像をBase64形式に変換 |
| ゴミ分類判定 | Google Gemini API | カレンダーデータと画像/テキストを組み合わせてAIが判定 |
| 返信 | LINE Reply API | 判定結果をユーザーへ返信 |

## 🔗 2つのフローの関係

```
 PDFアップロードフロー          LINEメッセージフロー
        │                              │
        ▼                              ▼
  Googleカレンダー              Supabase DB
  へ予定を登録           ──►   (parsed_pdfs)
                                ゴミ収集データ
                                       │
                                       ▼
                              Gemini が参照して
                              ゴミ分類・収集日を回答
```

PDFアップロードで登録したカレンダーデータが、LINEボットの回答の「元データ」として使われます。
つまり、**まずPDFをアップロードしてカレンダーを登録しておくことが、LINEボットを正確に使うための前提**となっています。
